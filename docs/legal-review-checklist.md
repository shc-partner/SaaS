# Legal Review Checklist (초안 / Draft)

> ⚠️ **본 문서는 초안입니다.** 본 체크리스트는 법률 검토를 **대체하지 않으며**, 변호사·전문가에게 전달할 검토 항목을 정리한 자료다.

본 체크리스트는 [terms-of-service-draft.md](terms-of-service-draft.md), [privacy-policy-draft.md](privacy-policy-draft.md), [refund-cancellation-policy.md](refund-cancellation-policy.md), [service-lifecycle-policy.md](service-lifecycle-policy.md), [export-and-migration-policy.md](export-and-migration-policy.md)와 한 세트로 검토되어야 한다.

## 1. 변호사 검토가 필요한 조항

### 1.1 이용약관(ToS)
- [ ] 약관의 명시·동의 절차 (전자상거래법 §13)
- [ ] 책임 제한 조항(12개월 결제액 한도)의 약관규제법 §8 위반 여부
- [ ] 면책 조항의 범위와 소비자 보호 조항 우선 적용 여부
- [ ] 자동 갱신 조항의 명시·동의·해지 절차 적합성
- [ ] 회사 측 일방 약관 변경권의 범위와 통지 의무
- [ ] 콘텐츠 라이선스 조항(회사가 가지는 제한적 라이선스의 범위)
- [ ] 분쟁 해결·관할 법원 조항의 소비자보호법 우선 원칙 부합

### 1.2 개인정보처리방침
- [ ] 수집 항목·목적·보유기간 표기의 PIPA §15·17·21 부합
- [ ] 처리 위탁 고지·동의 절차 (PIPA §26)
- [ ] 사이트 회원·예약자 데이터에 대한 회사의 **수탁자 지위** 법적 명확화 (B2B2C 구조)
- [ ] 14세 미만 아동 정보 처리 가능성 및 별도 동의 절차
- [ ] 개인정보 보호책임자 지정·고지

### 1.3 환불/해지
- [ ] 청약철회권 7일 산정·"실질 사용" 정의의 적법성
- [ ] 디지털 콘텐츠 청약철회 예외 조항 적용 가능 여부
- [ ] 일할 환불 산식의 부당약관 여부
- [ ] 약관 위반 강제 해지 시 무환불의 정당성

## 2. 개인정보처리방침 — 국가별 법률 검토 필요 항목

### 2.1 한국 (PIPA)
- [ ] 표준 개인정보처리방침 양식 부합
- [ ] 정보주체 권리행사 절차 명시
- [ ] 자동 수집 정보(쿠키·로그) 동의·통지

### 2.2 EU (GDPR) — 국외 이용자 가능성 시
- [ ] 적법 처리 근거(동의·계약·정당한 이익)
- [ ] DPO(Data Protection Officer) 지정 의무 검토
- [ ] 정보주체 권리(액세스·삭제·이동·이의)
- [ ] EU → 비EU 데이터 이전 시 SCC 또는 적정성 결정
- [ ] 침해 통지 72시간 의무
- [ ] 쿠키·동의 배너 (ePrivacy)

### 2.3 미국 (CCPA/CPRA, 캘리포니아 거주자 대상 시)
- [ ] "Do Not Sell" 옵트아웃
- [ ] 12개월 이내 개인정보 카테고리 공개

### 2.4 기타 관할
- [ ] 일본 APPI, 중국 PIPL, 브라질 LGPD 등 — 실제 이용자 발생 시 검토

---

## 3. 결제/세금/전자상거래/청약철회 검토 포인트

- [ ] 결제대행사 계약·PCI-DSS 책임 분담
- [ ] 세금계산서·현금영수증 발급 의무 (사업자 vs 개인 구분)
- [ ] 부가가치세 표기 방식 (가격 표시 광고법)
- [ ] 통신판매업 신고 의무
- [ ] 자동 결제 갱신 사전 고지 의무
- [ ] 디지털 콘텐츠·서비스의 청약철회권 예외 적용 여부
- [ ] 미성년자 결제 환불 절차
- [ ] 국외 결제·환차손·세무 처리

---

## 4. 로그/보안/감사기록 보관 기준 검토 포인트

- [ ] 통신비밀보호법상 통신사실확인자료 보관 의무 적용 여부
- [ ] 정보통신망법상 침해사고 대응 기록 보관
- [ ] 접속 로그·인증 로그·권한 변경 로그의 보관 기간 적정성
- [ ] 감사 로그의 무결성 보장 방법(append-only, 해시 체인 등)
- [ ] 로그 내 개인정보 마스킹 정책
- [ ] 로그 접근 권한·접근 기록 별도 보관

---

## 5. 고객 데이터 삭제 vs 보관 예외 충돌 검토 포인트

핵심 충돌: **유예·단계 삭제 정책** vs **정보주체의 즉시 삭제 요구권** vs **법정 보관 의무**

- [ ] 정보주체 즉시 삭제 요청 시 처리 절차(운영 즉시 삭제 + 백업 만료 후 삭제)의 PIPA·GDPR 적합성
- [ ] 법정 보관 의무 데이터의 분리 보관·접근 통제·열람 거부 사유 표기
- [ ] 약관·정책에서 보관 예외를 명확히 고지했는지
- [ ] 백업 즉시 삭제가 기술적으로 어려운 경우의 "사실 고지 + 기한 약속" 방식의 적법성
- [ ] 사이트 운영자(이용자)의 사이트 회원 삭제 요청 처리 책임 범위

## 6. Export 이후 책임 분리 조항 검토 포인트

- [ ] export 산출물의 라이선스(회사 코드·제3자 OSS) 명시
- [ ] export 이후 데이터 보호 책임의 이용자 이전 명문화
- [ ] export 산출물 사용으로 발생한 제3자 손해에 대한 회사 면책 범위
- [ ] export 후 보안 패치·업데이트 책임 범위 (회사 무책임 명시)
- [ ] export 산출물 재판매·재배포 금지 또는 허용 범위
- [ ] export 산출물 내 결제·외부 API 키 미포함 명시

## 7. 추가 점검(아키텍처-법무 정합성)

- [ ] `site.status` 상태 머신이 약관·환불·개인정보 정책의 단계와 1:1 매핑되는지
- [ ] 모든 정책 문서의 보존 기간 수치가 서로 일치하는지 (grace 30일·백업 30일·보관 의무 별표 등)
- [ ] dedicated stack 분리 시 데이터 처리 위탁 관계의 변동(고객이 수탁자 변경 동의 필요 여부)
- [ ] 운영자(SaaS 제공자)와 이용자(사이트 운영자) 간 PII 처리 역할의 명확한 구분 표기
