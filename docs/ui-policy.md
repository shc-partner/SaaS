# UI Policy — Platform vs Deliverable

> 본 문서는 SiteForge 의 UI 가 어디서는 데스크탑 전용이고 어디서는 반응형이어야 하는지를
> 단일 진실원으로 정의한다. 다른 문서·코드는 본 문서와 충돌하면 본 문서를 따른다.

## 1. 한 줄 요약

| 대상 | 정책 |
|---|---|
| **Platform UI** (SaaS 자체: 가입/로그인, 대시보드, 위저드, 관리자) | **데스크탑 전용** |
| **Deliverable UI** (생성된 산출물 사이트의 공개 페이지) | **반응형 필수** (desktop / tablet / mobile) |

플랫폼은 PC 작업 도구다. 산출물은 일반 방문자가 보는 회사 홈페이지다. 사용 맥락이 다르므로 정책이 갈린다.

## 2. 적용 범위

### 2.1 데스크탑 전용 (Platform UI)

| 위치 | 대상 화면 |
|---|---|
| `platform-frontend/` | 랜딩, 가입/로그인 (예정), 사이트 생성 위저드 4단계, 생성 진행/다운로드, (예정) 프로젝트 대시보드 |
| 산출물 내부의 **관리자(Admin)** 화면 | 산출물 안의 `/admin` 경로 — 콘텐츠 수정 도구 |

원칙:
- **viewport meta 는 데스크탑 폭 고정.** `width=device-width` 가 아니라 `width=1024` 같은 고정값.
- **모바일/태블릿용 미디어쿼리를 두지 않는다.** 작은 화면에서 가로 스크롤이 노출되는 것이 정상.
- **햄버거 메뉴, 슬라이드 패널, 터치 제스처 같은 모바일 전용 UX 도입 금지.**
- **테스트 대상도 데스크탑 해상도(>= 1024px)** 만. 모바일 회귀 테스트는 정의하지 않는다.

이유:
- Stage 1 의 사용자는 회사를 만드는 사장/관리자이고, 생성/관리 작업은 PC 환경에서 이루어진다.
- 위저드는 입력 필드가 많고 좌/우 분할 미리보기가 본질적이라 작은 화면에 맞추는 비용이 크다.
- 모바일 대응을 억지로 넣으면 코드 두 벌(데스크탑 + 모바일) 유지 부담이 발생하고, 실제 사용 빈도 대비 ROI 가 낮다.

### 2.2 반응형 필수 (Deliverable UI)

| 위치 | 대상 화면 |
|---|---|
| `templates/company-intro/frontend/` | 산출물(생성된 기업 소개 사이트) 의 공개 페이지: 홈, 회사 소개, 서비스, 문의 |
| 향후 추가될 다른 산출물 템플릿 (`templates/<type>/frontend/`) | 동일 정책 적용 |

원칙:
- **viewport meta 는 `width=device-width, initial-scale=1`.**
- **mobile-first CSS.** 기본 레이아웃을 좁은 화면 기준으로 짜고 미디어쿼리로 데스크탑을 확장한다.
- **표준 breakpoint** (가이드라인, 강제 아님):
  - 모바일: ~ 640px
  - 태블릿: 641 ~ 1024px
  - 데스크탑: 1025px ~
- **헤더/내비게이션은 모바일에서 햄버거 또는 드로어**, 데스크탑에서 가로 메뉴.
- **이미지는 `max-width: 100%`** 로 컨테이너 안에 갇히게.
- **글자 크기, 패딩** 도 화면별로 자연스럽게 줄/늘게 한다 (rem + 미디어쿼리, 또는 `clamp()`).
- **메뉴 구조가 모바일에서 깨지지 않게** — 긴 라벨, 메뉴 개수가 늘어도 1열 펼침이 가능해야 한다.

이유:
- 산출물의 최종 방문자는 회사를 검색해 들어오는 일반 사용자이며, 트래픽의 절반 이상이 모바일이다.
- 산출물이 모바일에서 깨지면 고객사가 SiteForge 자체를 부정평가하므로 Stage 1 의 평판 리스크 1순위.
- 산출물은 SiteForge 의 "결과물 견본" 이기도 하다 — 다음 고객 유치의 데모로 쓰인다.

## 3. 위치별 책임 매트릭스

| 위치 | UI 정책 | 비고 |
|---|---|---|
| `platform-frontend/` | 데스크탑 전용 | viewport `width=1024`, `body { min-width: 1024px }` 강제 |
| `platform-backend/` | UI 없음 | API 응답만, 영향 없음 |
| `templates/company-intro/frontend/` | 반응형 필수 | viewport `width=device-width`, mobile-first CSS |
| `templates/<future-type>/frontend/` | 반응형 필수 | 동일 |
| 산출물 내부의 `/admin` (생성 결과) | 데스크탑 전용 | 사이트 운영자가 PC 에서 쓴다는 가정 |

## 4. 자주 헷갈리는 케이스

- **"위저드 화면을 모바일에서 좀 보기 좋게 해줘"** → 거절. 정책상 미지원. 데스크탑에서만 평가한다.
- **"산출물 미리보기를 위저드 안에 넣을 때 미리보기는 반응형이어야 하나?"** → 미리보기는 산출물의 모양을 흉내 내므로, 그 안에서는 반응형이 맞다. 단, 미리보기를 감싸는 위저드 셸은 데스크탑 전용.
- **"산출물 관리자도 반응형이 좋지 않을까?"** → Stage 1 에서는 No. 운영자가 PC 에서 쓴다는 가정. Stage 2 이후 재검토.
- **"생성기에서 모바일 미리보기 토글을 제공해야 하나?"** → 산출물의 반응형이 잘 동작하는지 검증하는 도구는 가치가 있다. 다만 그 도구의 UI 자체는 데스크탑 전용으로 충분하다.

## 5. 코드 레벨 가드

- `platform-frontend/index.html` — viewport meta 가 `width=1024` 로 고정.
- `platform-frontend/src/styles.css` — 상단 배너 코멘트 + `body { min-width: 1024px }`.
- `templates/company-intro/frontend/` — viewport meta 가 `width=device-width`, base 스타일이 mobile-first.

위 가드를 임의로 바꾸려면 본 문서를 먼저 갱신할 것.
